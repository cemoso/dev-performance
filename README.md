# Developer Performance Review Framework

## Executive Summary

An evidence-anchored framework for evaluating software developer performance across five core competencies. Designed for quarterly reviews with annual summaries.

### Key Features

- **Standardized scoring** (1-5 scale) against written anchors
- **Weighted categories** reflecting organizational priorities
- **Evidence-based assessment** with written 1 / 3 / 5 anchors per criterion
- **Level-calibrated**: scored against expectations for the developer's current role
- **No activity counts**: commits, PR counts, and bot pass rates are never scored
- **Goal tracking** for continuous professional development

### Evaluation Categories

| Category | Weight | Focus |
|----------|--------|-------|
| Technical Growth & Problem Solving | 20% | Learning, innovation, technical debt reduction |
| Knowledge Distribution & Bus Factor | 25% | Documentation, API contracts, handoff readiness, cross-training |
| Output & Code Quality | 25% | Delivery predictability, reviewable changes, risk-adjusted defects, testing, standards |
| Continuous Improvement (Kaizen) | 15% | Adopted process improvements, retrospectives, growth goals |
| Collaboration & Communication | 15% | Code reviews, unblocking, clear updates, escalation, mentoring, team friction |

### Performance Ratings

| Total Score | Rating |
|-------------|--------|
| 90 to 100 | Exceptional |
| 70 to below 90 | Exceeds Expectations |
| 50 to below 70 | Meets Expectations |
| 30 to below 50 | Needs Improvement |
| Below 30 | Does Not Meet Expectations |

Each criterion is scored 1-5. Category totals are normalized by weight: `(score ÷ max) × weight`, summing to 100.
